## 一、原版本的問題與改善方法

| # | 問題 | 改善方法 |
|---|------|---------|
| 1 | 以「切片」為單位計算醫師共識。LIDC 由 4 位醫師獨立判讀，同一切片可能有多顆結節；A 醫師標結節甲、B 醫師標結節乙會被誤判為兩人對同一顆有共識，後續 9 項特徵取中位數時亦混合不同結節的評分 | 以 `cluster_annotations()` 依三維位置將標記歸群為物理結節，共識判斷改於結節層級進行 |
| 2 | 每張切片僅保留面積最大的輪廓。被捨棄的結節在標準答案中成為背景，等同標註真實病灶為「無」；被捨棄者通常是較小的結節，而小結節正是偵測任務中最困難的部分 | 一張切片上所有通過共識門檻的結節全數保留 |
| 3 | 逐張切片 min-max 正規化，未套用 RescaleSlope/Intercept 轉為 HU、亦未做窗寬窗位處理。實測 HU 範圍達 −2048 至 8155，極端值來自掃描視野外區域與金屬植入物；含金屬的切片整張被壓暗，同一結節在相鄰切片呈現不同亮度 | 轉為 HU 後套用固定肺窗（WC −600 / WW 1500） |
| 4 | 前處理與推論端的灰階處理不一致（min-max vs 肺窗），構成 train-test skew。此問題在訓練指標上無法察覺，因驗證集與訓練集使用相同的前處理 | 兩端統一為肺窗 |
| 5 | 供 YOLO 使用的標註皆為固定值 `0 0.5 0.5 0.125 0.125`。該資料集由「以結節為中心裁切」的 256×256 影像構成，標準答案被裁切幾何決定，一個固定輸出中央框的規則即可獲得接近滿分 | 改用完整 512×512 切片，框由 `consensus(clevel=0.5)` 依醫師標註計算 |
| 6 | 訓練集不含任何無結節的影像，模型無從學習「此處無結節」 | 自同批病人抽取無結節切片作為負樣本 |
| 7 | 訓練用 256×256 置中裁切、推論餵完整 512×512 切片，兩者的尺寸、內容範圍、結節位置分布皆不同 | 訓練即使用完整切片 |
| 8 | 訓練時 `val=False, save=False, plots=False`，全程無監控，且僅保留最後一輪的權重而非驗證表現最佳者 | 三項全數開啟，並設 `patience=30` 提早停止 |
| 9 | 載入 `yolo11m-seg.pt`（分割模型）執行偵測任務；同時設 `pretrained=False` 卻又載入預訓練權重，兩者矛盾 | 使用 `yolo11n.pt` 偵測版本，明確載入 COCO 預訓練權重 |
| 10 | 未設 `seed` 與 `deterministic`，同一份程式碼兩次執行結果不同，無法重現 | 固定亂數種子並開啟確定性模式 |
| 11 | 資料切分未見明確的病人層級保證。同一病人的相鄰切片高度相似，若隨機切分，模型於訓練時等同看過測試集的近乎相同影像 | 明確依病人 ID 切分，並以 assert 驗證三組無重疊 |
| 12 | 以切片為單位評估。結節橫跨多張切片，此方式無法回答「整顆結節是否被發現」 | 3D 聚合後以病灶為單位計分，採 LUNA16 協定 |
| 13 | 「Bootstrap 95% CI [1.000, 1.000]」：33 個樣本全對時，任何重採樣皆不會出現錯誤，該區間為數學上的必然而非證據強度 | 樣本有誤時正常做 bootstrap（以病人為單位）；全對時改用 rule of three |
| 14 | 三套並存的前處理腳本且無文件說明何者為正式版、重複檔案、硬編路徑、`requirements.txt` 缺套件、無實驗紀錄 | 重建版採用單一前處理流程（原有腳本未更動），路徑改為參數，補齊相依並註記版本限制原因，每次訓練自動記錄設定 |

## 二、重建流程

```
環境建置 → 資料下載 → 前處理 → 目視驗證 → 病人層級切分 → 訓練 → 病灶層級評估
```

### 環境

前處理與訓練分為兩個 conda 環境。pylidc 相依舊版 numpy 與 SQLAlchemy，與 ultralytics 的需求衝突。

版本鎖定原因：`numpy<1.24`（1.24 移除 `np.int`）、`sqlalchemy<2.0`（變更了 pylidc 使用的 Query API）、`setuptools<81`（移除 pylidc 於 import 時需要的 `pkg_resources`）。

另一個易踩的陷阱：PyPI 上的 torch 是 CPU 版，直接 `pip install ultralytics` 會使 `torch.cuda.is_available()` 為 False，須從 PyTorch 官方來源安裝 CUDA 版。

### 前處理

`cluster_annotations()` 歸群 → 篩共識 ≥3 位 → `consensus(0.5)` 計算框 → 轉肺窗存 PNG → 抽負樣本 → 輸出 YOLO 標註與 manifest。

產出：696 位病人、19,714 張影像（正 7,888 / 負 11,826）、8,208 個框、1,392 顆合格結節。含多顆結節的切片 309 張。

### 目視驗證

將框畫回影像確認。灰階平均值約 107、跨病人亮度一致、框貼合病灶且大小隨結節變化、多結節切片每顆皆有框。

數字正確不代表影像正確——框偏移、座標軸顛倒這類錯誤不會產生錯誤訊息。

### 切分

病人層級分層切分 70/15/15 → 487 / 105 / 104 位病人，框數比例 70.1% / 15.0% / 14.9%。

註：train 的切片厚度中位數為 2.00mm，val/test 為 1.25mm。分層依框數進行，厚度未納入條件。

### 訓練

YOLO11n + COCO 預訓練，imgsz 640、batch 8、patience 30。

### 評估

3D 聚合 → LUNA16 病灶層級匹配 → FROC 曲線與 CPM → 病人層級 bootstrap 信賴區間。

## 三、設計決定

**框的幾何：`consensus(clevel=0.5)`**
4 位醫師畫出 4 個不同輪廓（實測同一顆結節的直徑可差 43%：19.5 / 27.7 / 28.0 / 20.6 mm），但 YOLO 標註只能有一個框。`clevel=0.5` 取至少半數醫師認定屬於病灶的像素。替代方案為取聯集（框偏大）或取交集（可能切掉毛刺狀邊緣，而該特徵與惡性度相關）。選 0.5 因定義明確，優於「取最大」這類任意規則。

**共識門檻：≥3 位醫師**
與 LUNA16 標準一致，結果可與文獻對照；設為 2 則需自行解釋。實際代價高於預期：2,651 顆結節中僅 1,392 顆合格，排除 48%（771 顆僅 1 位醫師標記、488 顆有 2 位）。改為 ≥2 可增加約 29% 的資料量，對照實驗尚未進行。

**低共識結節：連同該切片排除**
若僅移除標註而保留影像，圖中會存在一顆真實但未標註的結節，與問題 2 是同類錯誤。不將其標註的理由是：設定門檻本身即表示判斷 1–2 位醫師的標記可信度不足，標註上去等於自我矛盾。故只能整張排除，以一張訓練影像換掉一個錯誤標註。

**切片厚度：不篩選，但記錄於 manifest**
實測中位數 2.0mm，≤2.5mm 者佔 88%，篩選僅損失一成多。保留可供後續分析模型在薄／厚切片上的表現差異。厚切片吃虧兩處：結節物理大小固定，切得越厚產出的訓練影像越少（實測一顆 20–28mm 結節在 3mm 切片上僅出現 6 張，1mm 切片約 20 張）；且部分容積效應使小結節邊界模糊。

**負樣本：正樣本 × 1.5，取自同批病人，距標註切片 ≥2 張**
一次掃描約 200–300 張切片，含結節者僅 10–20 張，全數保留將使九成以上為背景，模型會傾向一律回答「無」。負樣本必須與正樣本同源：若取自其他病人，可能存在機器型號、重建演算法等系統性差異，模型會學到「這台機器拍的沒有結節」這類捷徑（confounding），訓練指標漂亮但實際無效。`NEG_MARGIN=2` 是因結節為立體，邊緣切片可能仍有殘影。

**輸出格式：8-bit 灰階 PNG**
一致性優先——推論端輸出即為 8-bit。肺窗已截斷範圍，256 階對偵測足夠，且可直接開啟目視除錯。

**肺窗：WC −600 / WW 1500**
文獻常用的胸腔標準設定，但選它的主因是與推論端現行值一致。關鍵在於訓練與推論只能有一組數字，並非此組最優；文獻上窗位在 −450 至 −700 之間皆屬合理範圍。

**資料集：續用 LIDC-IDRI，不改用 LUNA16**
LUNA16 的標註品質、真實框大小、天然的病人層級切分皆為現成，技術上省事。但「同一份資料、改進方法」的對照最乾淨——換資料集會使「數字變化源於方法或資料」難以區分。

（過程中一度誤以為原專題使用 LUNA16，因 `dataloader.py` 有 `LUNA16_DIR` 變數名，但其實際掃描的是 LIDC 的 XML 格式。向組員確認後確定為 LIDC，變數名為誤植。）

**切分：病人層級 + 分層 + assert 驗證**
分層依每位病人的框數排序後逐一分配給「目前最缺人」的組別，避免多結節病人集中於某組或測試集全為簡單案例。三個 assert 檢查組間無重疊——資料洩漏是「不會報錯但結果全錯」的問題，以 assert 將其轉為會中斷執行的錯誤。

**預訓練權重：使用 COCO 預訓練**
訓練框僅 5,754 個，從零開始會嚴重過擬合——模型連基礎的邊緣與形狀特徵都要從這些樣本學起。雖然 COCO 為日常照片、本任務為 CT，低層次視覺特徵是共通的，這是醫學影像領域的標準做法。

**模型：yolo11n 偵測版，非 yolo11m-seg**
本任務只需框，不需逐像素分割。使用分割模型是不必要的複雜化，也可能是原版本 `best.pt` 達 114MB 的原因——本次產出的 `best.pt` 為 5.5MB。

**資料增強：依 CT 特性調整**

| 參數 | 預設 | 調整為 | 理由 |
|---|---|---|---|
| hsv_h, hsv_s | 有 | 0 | 灰階影像無色相與飽和度資訊 |
| hsv_v | 0.4 | 0.15 | 本次重建的核心為統一灰階標準，過大的亮度抖動會重新引入該變異 |
| flipud | 0 | 0 | 上下翻轉的胸腔影像解剖上不存在 |
| fliplr | 0.5 | 0.5 | 左右鏡像雖然左右肺結構不同，但對「找出團塊」仍屬合理變化 |
| degrees | 0 | 10 | 病人擺位傾斜是真實存在的變異 |

**信賴區間：以病人為單位 bootstrap**
同一病人的多顆結節共用掃描儀、重建參數與該病人的解剖特徵，彼此相關。以結節為單位重抽等於假設其獨立，會高估有效樣本數，使區間過窄、看起來比實際更精確。

`evaluate.py` 另實作了 rule of three，供召回率為 1.0（bootstrap 將退化為 [1.0, 1.0]）時使用。本次實驗的召回率皆未達 1.0，該分支尚未被觸發。

## 四、實驗紀錄

### mosaic 增強：從初步結論到修正

文獻指出 mosaic 拼接四張影像，會破壞 CT 解剖結構的空間連續性，理論上不適用於醫學影像。

| | 159 位病人 | | 696 位病人 | |
|---|---|---|---|---|
| | mosaic 開 | mosaic 關 | mosaic 開 | mosaic 關 |
| CPM | 0.873 | 0.845 | 0.827 | 0.845 |
| 召回率 @2FP | 0.913 | 0.848 | 0.884 | 0.874 |
| 95% CI | [0.796, 1.000] | — | [0.837, 0.935] | [0.826, 0.926] |
| val 結節數 | 46 | 46 | 207 | 207 |

初步實驗（159 位）顯示關閉後表現下降 0.065，似與文獻預期相反。但該次的信賴區間寬達 ±0.10，兩組大幅重疊，差異未達可辨識的程度。

擴增至 696 位病人重測後，差異縮小至 0.01 且方向不一致（CPM 為關閉較好、召回率為開啟較好），兩組信賴區間幾乎完全重疊。

**結論**：在本任務的資料量下，mosaic 對結果無可辨識的影響。初步觀察到的差異應為小樣本雜訊。

註：第一次訓練（159 位、mosaic 開）的 `experiment.json` 因路徑處理錯誤未能寫出，其設定與後續三次相同，僅資料量不同。該錯誤已修正（改由 `model.trainer.save_dir` 取得實際輸出位置）。

### 資料量擴增：數字下降但可信度提升

| | 159 位病人 | 696 位病人 |
|---|---|---|
| val 結節數 | 46 | 207 |
| 召回率 @2FP | 0.913 | 0.884 |
| 95% CI | [0.796, 1.000] | [0.837, 0.935] |
| 區間寬度 | ±0.10 | ±0.05 |

召回率下降 0.029，但信賴區間收窄一半。

數字下降並非模型退步：46 顆結節中漏 4 顆為 0.913，207 顆中漏 24 顆為 0.884；後者涵蓋更多樣的病人與困難案例，更接近真實表現。且舊的 0.913 落在新區間之外，而新的 0.884 落在舊區間內（0.796–1.000），顯示先前的估計本身即不精確。

FROC 曲線的形狀亦改善：159 位版在低假陽性區近乎持平（0.783 → 0.826），696 位版則穩定上升（0.647 → 0.850），顯示模型的信心分數更具鑑別力。
