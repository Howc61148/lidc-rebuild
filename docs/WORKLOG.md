## 一、原版本的問題與改善方法

| # | 問題 | 改善方法 |
|---|------|---------|
| 1 | 以「切片」為單位計算醫師共識。LIDC 由 4 位醫師獨立判讀，同一切片可能有多顆結節；A 醫師標結節甲、B 醫師標結節乙會被誤判為兩人對同一顆有共識，後續 9 項特徵取中位數時亦混合不同結節的評分 | 以 `cluster_annotations()` 依三維位置將標記歸群為物理結節，共識判斷改於結節層級進行 |
| 2 | 每張切片僅保留面積最大的輪廓。被捨棄的結節在標準答案中成為背景，等同標註真實病灶為「無」；被捨棄者通常是較小的結節，而小結節正是偵測任務中最困難的部分 | 一張切片上所有通過共識門檻的結節全數保留 |
| 3 | 逐張切片 min-max 正規化，未套用 RescaleSlope/Intercept 轉為 HU、亦未做窗寬窗位處理。實測 HU 範圍達 −2048 至 8155，極端值來自掃描視野外區域與金屬植入物；含金屬的切片整張被壓暗，同一結節在相鄰切片呈現不同亮度 | 轉為 HU 後套用固定肺窗（WC −600 / WW 1500） |
| 4 | 前處理與推論端的灰階處理不一致（min-max vs 肺窗），構成 train-test skew。此問題在訓練指標上無法察覺，因驗證集與訓練集使用相同的前處理 | 兩端統一為肺窗 |
| 5 | 原 repo 中另有一條 YOLO 資料建置路線（`build_lidc_yolo.py`）：以結節置中裁切的 256×256 影像為輸入，標註皆為固定值 `0 0.5 0.5 0.125 0.125`，不含無結節影像。依原專題報告，部署模型係以 Roboflow 平台的真實標註訓練，該腳本是否曾用於部署無法確認 | 重建版以完整 512×512 切片為輸入，框由 `consensus(clevel=0.5)` 依醫師標註計算，並自同批病人抽取負樣本 |
| 6 | 訓練時 `val=False, save=False, plots=False`，全程無監控，且僅保留最後一輪的權重而非驗證表現最佳者 | 三項全數開啟，並設 `patience=30` 提早停止 |
| 7 | 採用 YOLOv11x（最大參數量版本）並**關閉預訓練權重**從零訓練。訓練框數量有限時，從零開始須自基礎視覺特徵學起，容易過擬合；且 x 版本的容量對本任務的資料量而言明顯過大 | 使用 `yolo11n`／`yolo11s` 並載入 COCO 預訓練權重 |
| 8 | 未設 `seed` 與 `deterministic`，同一份程式碼兩次執行結果不同，無法重現 | 固定亂數種子並開啟確定性模式 |
| 9 | 資料切分為隨機分配而非病人層級。原專題報告「未來展望」一節載明：「隨機分配在數據集（訓練集、驗證集、測試集）中，使得同一病人的切片可能在不同數據集之中」。同一病人的相鄰切片高度相似，此種切分使模型於訓練時等同看過測試集的近乎相同影像 | 明確依病人 ID 切分，並以 assert 驗證三組無重疊 |
| 10 | 以切片為單位評估。結節橫跨多張切片，此方式無法回答「整顆結節是否被發現」 | 以病灶為單位計分；命中規則參考 LUNA16（三維 mm 距離 < 半徑），詳見第四節「評估方法的修正」 |
| 11 | 「Bootstrap 95% CI [1.000, 1.000]」：33 個樣本全對時，任何重採樣皆不會出現錯誤，該區間為數學上的必然而非證據強度 | 樣本有誤時正常做 bootstrap（以病人為單位）；全對時改用 rule of three |
| 12 | 三套並存的前處理腳本且無文件說明何者為正式版、重複檔案、硬編路徑、`requirements.txt` 缺套件、無實驗紀錄 | 重建版採用單一前處理流程（原有腳本未更動），路徑改為參數，補齊相依並註記版本限制原因，每次訓練自動記錄設定 |
| 13 | 資料集的描述前後不一致。原專題報告稱採用 LUNA16，但同一節隨即敘述「將 LUNA16 數據集中，xml 檔案所標記的切片提取出來」——LUNA16 並無 XML 標註，該格式屬於 LIDC-IDRI。程式碼中亦見 `LUNA16_DIR` 變數而實際掃描 LIDC 的 XML | 重建版明確使用 LIDC-IDRI，並以 pylidc 讀取標註 |

註：重建過程中亦於自身程式發現一項檔名衝突問題，詳見第四節。

## 二、重建流程

```
環境建置 → 資料下載 → 前處理 → 目視驗證 → 病人層級切分 → 訓練 → 病灶層級評估
```

### 環境

前處理與訓練分為兩個 conda 環境。pylidc 相依舊版 numpy 與 SQLAlchemy，與 ultralytics 的需求衝突。

版本鎖定原因：`numpy<1.24`（1.24 移除 `np.int`）、`sqlalchemy<2.0`（變更了 pylidc 使用的 Query API）、`setuptools<81`（移除 pylidc 於 import 時需要的 `pkg_resources`）。

另一個易踩的陷阱：PyPI 上的 torch 是 CPU 版，直接 `pip install ultralytics` 會使 `torch.cuda.is_available()` 為 False，須從 PyTorch 官方來源安裝 CUDA 版。

### 前處理

`cluster_annotations()` 歸群 → 篩共識 ≥3 位 → `consensus(0.5)` 計算框 → 轉肺窗存 PNG → 抽負樣本 → 輸出 YOLO 標註與 manifest。

產出：696 位病人、19,714 張影像（正 7,888 / 負 11,826）、8,208 個框、1,392 顆合格結節。含多顆結節的切片 309 張。

### 目視驗證

將框畫回影像確認。灰階平均值約 107、跨病人亮度一致、框貼合病灶且大小隨結節變化、多結節切片每顆皆有框。

數字正確不代表影像正確——框偏移、座標軸顛倒這類錯誤不會產生錯誤訊息。

### 切分

病人層級分層切分 70/15/15 → 487 / 105 / 104 位病人，框數比例 70.1% / 15.0% / 14.9%。

註：train 的切片厚度中位數為 2.00mm，val/test 為 1.25mm。分層依框數進行，厚度未納入條件。

### 訓練

YOLO11n + COCO 預訓練，imgsz 640、batch 8、patience 30。

### 評估

3D 聚合 → LUNA16 病灶層級匹配 → FROC 曲線與 CPM → 病人層級 bootstrap 信賴區間。

## 三、設計決定

**框的幾何：`consensus(clevel=0.5)`**
4 位醫師畫出 4 個不同輪廓（實測同一顆結節的直徑可差 43%：19.5 / 27.7 / 28.0 / 20.6 mm），但 YOLO 標註只能有一個框。`clevel=0.5` 取至少半數醫師認定屬於病灶的像素。替代方案為取聯集（框偏大）或取交集（可能切掉毛刺狀邊緣，而該特徵與惡性度相關）。選 0.5 因定義明確，優於「取最大」這類任意規則。

**共識門檻：≥3 位醫師**
與 LUNA16 標準一致，結果可與文獻對照；設為 2 則需自行解釋。實際代價高於預期：2,651 顆結節中僅 1,392 顆合格，排除 48%（771 顆僅 1 位醫師標記、488 顆有 2 位）。改為 ≥2 可增加約 29% 的資料量，對照實驗尚未進行。

**低共識結節：連同該切片排除**
若僅移除標註而保留影像，圖中會存在一顆真實但未標註的結節，與問題 2 是同類錯誤。不將其標註的理由是：設定門檻本身即表示判斷 1–2 位醫師的標記可信度不足，標註上去等於自我矛盾。故只能整張排除，以一張訓練影像換掉一個錯誤標註。

**切片厚度：不篩選，但記錄於 manifest**
實測中位數 2.0mm，≤2.5mm 者佔 88%，篩選僅損失一成多。保留可供後續分析模型在薄／厚切片上的表現差異。厚切片吃虧兩處：結節物理大小固定，切得越厚產出的訓練影像越少（實測一顆 20–28mm 結節在 3mm 切片上僅出現 6 張，1mm 切片約 20 張）；且部分容積效應使小結節邊界模糊。

**負樣本：正樣本 × 1.5，取自同批病人，距標註切片 ≥2 張**
一次掃描約 200–300 張切片，含結節者僅 10–20 張，全數保留將使九成以上為背景，模型會傾向一律回答「無」。負樣本必須與正樣本同源：若取自其他病人，可能存在機器型號、重建演算法等系統性差異，模型會學到「這台機器拍的沒有結節」這類捷徑（confounding），訓練指標漂亮但實際無效。`NEG_MARGIN=2` 是因結節為立體，邊緣切片可能仍有殘影。

**輸出格式：8-bit 灰階 PNG**
一致性優先——推論端輸出即為 8-bit。肺窗已截斷範圍，256 階對偵測足夠，且可直接開啟目視除錯。

**肺窗：WC −600 / WW 1500**
文獻常用的胸腔標準設定，但選它的主因是與推論端現行值一致。關鍵在於訓練與推論只能有一組數字，並非此組最優；文獻上窗位在 −450 至 −700 之間皆屬合理範圍。

**資料集：續用 LIDC-IDRI，不改用 LUNA16**
LUNA16 的標註品質、真實框大小、天然的病人層級切分皆為現成，技術上省事。但「同一份資料、改進方法」的對照最乾淨——換資料集會使「數字變化源於方法或資料」難以區分。

（過程中一度誤以為原專題使用 LUNA16，因 `dataloader.py` 有 `LUNA16_DIR` 變數名，但其實際掃描的是 LIDC 的 XML 格式。向組員確認後確定為 LIDC。後續查閱原專題報告發現，報告中亦將資料集稱為 LUNA16 而同時敘述 XML 標註，此一名稱上的混用貫穿文件與程式碼，詳見第四節。）

**切分：病人層級 + 分層 + assert 驗證**
分層依每位病人的框數排序後逐一分配給「目前最缺人」的組別，避免多結節病人集中於某組或測試集全為簡單案例。三個 assert 檢查組間無重疊——資料洩漏是「不會報錯但結果全錯」的問題，以 assert 將其轉為會中斷執行的錯誤。

**預訓練權重：使用 COCO 預訓練**
訓練框僅 5,754 個，從零開始會嚴重過擬合——模型連基礎的邊緣與形狀特徵都要從這些樣本學起。雖然 COCO 為日常照片、本任務為 CT，低層次視覺特徵是共通的，這是醫學影像領域的標準做法。

**模型：yolo11n 偵測版，非 yolo11m-seg**
本任務只需框，不需逐像素分割。使用分割模型是不必要的複雜化，也可能是原版本 `best.pt` 達 114MB 的原因——本次產出的 `best.pt` 為 5.5MB。

**資料增強：依 CT 特性調整**

| 參數 | 預設 | 調整為 | 理由 |
|---|---|---|---|
| hsv_h, hsv_s | 有 | 0 | 灰階影像無色相與飽和度資訊 |
| hsv_v | 0.4 | 0.15 | 本次重建的核心為統一灰階標準，過大的亮度抖動會重新引入該變異 |
| flipud | 0 | 0 | 上下翻轉的胸腔影像解剖上不存在 |
| fliplr | 0.5 | 0.5 | 左右鏡像雖然左右肺結構不同，但對「找出團塊」仍屬合理變化 |
| degrees | 0 | 10 | 病人擺位傾斜是真實存在的變異 |

**信賴區間：以病人為單位 bootstrap**
同一病人的多顆結節共用掃描儀、重建參數與該病人的解剖特徵，彼此相關。以結節為單位重抽等於假設其獨立，會高估有效樣本數，使區間過窄、看起來比實際更精確。

`evaluate.py` 另實作了 rule of three，供召回率為 1.0（bootstrap 將退化為 [1.0, 1.0]）時使用。本次實驗的召回率皆未達 1.0，該分支尚未被觸發。

## 四、實驗紀錄

### mosaic 增強：從初步結論到修正

文獻指出 mosaic 拼接四張影像，會破壞 CT 解剖結構的空間連續性，理論上不適用於醫學影像。

| | 159 位病人 | | 696 位病人 | |
|---|---|---|---|---|
| | mosaic 開 | mosaic 關 | mosaic 開 | mosaic 關 |
| CPM | 0.873 | 0.845 | 0.827 | 0.845 |
| 召回率 @2FP | 0.913 | 0.848 | 0.884 | 0.874 |
| 95% CI | [0.796, 1.000] | — | [0.837, 0.935] | [0.826, 0.926] |
| val 結節數 | 46 | 46 | 207 | 207 |

初步實驗（159 位）顯示關閉後表現下降 0.065，似與文獻預期相反。但該次的信賴區間寬達 ±0.10，兩組大幅重疊，差異未達可辨識的程度。

擴增至 696 位病人重測後，差異縮小至 0.01 且方向不一致（CPM 為關閉較好、召回率為開啟較好），兩組信賴區間幾乎完全重疊。

**結論**：在本任務的資料量下，mosaic 對結果無可辨識的影響。初步觀察到的差異應為小樣本雜訊。

註：第一次訓練（159 位、mosaic 開）的 `experiment.json` 因路徑處理錯誤未能寫出，其設定與後續三次相同，僅資料量不同。該錯誤已修正（改由 `model.trainer.save_dir` 取得實際輸出位置）。

註：上表數字為檔名衝突修正前所測。修正後於相同權重重新評估，696 位／mosaic 開的 CPM 為 0.830、召回率 @2FP 為 0.885，變動在 0.003 以內。

### 資料量擴增：數字下降但可信度提升

| | 159 位病人 | 696 位病人 |
|---|---|---|
| val 結節數 | 46 | 207 |
| 召回率 @2FP | 0.913 | 0.884 |
| 95% CI | [0.796, 1.000] | [0.837, 0.935] |
| 區間寬度 | ±0.10 | ±0.05 |

召回率下降 0.029，但信賴區間收窄一半。

數字下降並非模型退步：46 顆結節中漏 4 顆為 0.913，207 顆中漏 24 顆為 0.884；後者涵蓋更多樣的病人與困難案例，更接近真實表現。且舊的 0.913 落在新區間之外，而新的 0.884 落在舊區間內（0.796–1.000），顯示先前的估計本身即不精確。

FROC 曲線的形狀亦改善：159 位版在低假陽性區近乎持平（0.783 → 0.826），696 位版則穩定上升（0.647 → 0.850），顯示模型的信心分數更具鑑別力。

### 檔名衝突：發現、修正與影響評估

比對 `manifest.csv` 的列數（19,714）與實際輸出的 PNG 檔案數（19,680）時發現不一致，相差 34 張。

**原因**：檔名由 `patient_id` 與切片編號組成，未計入同一位病人可能有多次掃描（LIDC-IDRI 中確實存在）。第二次掃描的輸出覆蓋了第一次的同名檔案。

**影響分析**：

- 影像與標註以相同檔名成對寫出，故被覆蓋者內容一致，不會產生錯誤標註
- 病人層級切分不受影響，兩次掃描的 `patient_id` 相同，必然分入同一組
- 但該病人的切片序列成為兩次掃描的混合，破壞了 3D 聚合「相鄰編號來自同一次掃描」的前提
- 評估時 `n_scans` 誤以病人數計算，使 FP/scan 的分母偏小

**修正**：檔名加入 `scan.id`；評估改以掃描為單位進行 3D 聚合與匹配，但 bootstrap 仍以病人為單位（同一病人的多次掃描不是獨立樣本）。

**修正後的影響量化**（yolo11n / 640，val 集）：

| | 修正前 | 修正後 |
|---|---|---|
| 掃描數 / 病人數 | 105 / 105 | 106 / 105 |
| 結節數 | 207 | 209 |
| 召回率 @2FP | 0.884 | 0.885 |
| CPM | 0.827 | 0.830 |
| 95% CI | [0.837, 0.935] | [0.839, 0.936] |

val 集中僅 1 位病人有兩次掃描。各項指標的變動在 0.003 以內，遠小於信賴區間寬度（±0.05），**先前四組實驗的結論不受影響**。

已於 `preprocess.py` 加入自動檢查：比對 manifest 列數、唯一檔名數與實際檔案數，不一致時發出警告。

**改善集中於低假陽性區**：在 0.125 FP/scan 的嚴格條件下提升 0.100，而 8 FP/scan 時完全相同。同時偵測總數由 1125 降至 979 而召回率上升，顯示模型的信心分數更具鑑別力——真結節獲得較高分數，因而在嚴格門檻下仍被保留。

兩組的信賴區間有相當程度的重疊，差異幅度小於區間寬度。但與 mosaic 實驗不同的是，七個取樣點全數同向（六升一平），無任何一點退步，故判斷此提升為真實，僅幅度的估計不夠精確。

**限制**：本次同時調整了兩個變數，無法區分模型大小與影像尺寸各自的貢獻。拆解需再執行兩次訓練（各 4–6 小時），基於時間考量未進行。

**觀察**：兩組模型在 8 FP/scan 時皆為 0.928，代表約 7% 的結節在任何門檻下皆未被偵測。此為方法本身的上限，非模型容量不足所致，需改變架構（如 2.5D 輸入或兩階段假陽性抑制）方有機會突破。

### 評估方法的修正（2026-09）

將 repo 與同組同學的原專題 repo 一併交由另一個語言模型審閱，其指出評估程式的三項問題；自行複查後再確認三項。

**審閱指出的**

1. FP/scan 只算了抽樣切片。評估讀取的是訓練用的 `test.txt`，僅含正樣本切片與 1.5 倍抽樣負樣本，每次掃描約 30 張；實際一次 CT 有 200–300 張，未被抽入的切片可能產生的誤報完全未被計入。
2. 命中規則非完整 LUNA16 協定。使用像素距離與自訂聚合條件，且未處理 LUNA16 的「忽略區」（打中非參考標準的結節不計分）。文件卻寫「依 LUNA16 協定」。
3. 標準答案由 2D 框重新聚合。`cluster_3d()` 以固定 30 像素為門檻，同一切片上相距較近的兩顆結節會被併為一顆。人工案例可重現此行為。

**自行複查再發現的**

4. 匹配時要求預測與標準答案的 z 中心相差 ≤ 2 張。橫跨 20 張的大結節若只被抓到一端，兩中心相差可達 8 張，明明抓到卻判為漏診。
5. 半徑以像素計，但各掃描的 pixel_spacing 從 0.46 到 0.98 mm 不等，同一像素數代表的實際距離差一倍。
6. 聚合後的信心分數以四捨五入的座標查表回填，座標碰撞時會互相覆蓋。

**修正**（`export_eval.py` + 重寫 `evaluate.py`，舊版保留為 `evaluate_v1_sampled.py`）

- 對 test 集每次掃描輸出全部切片（26,707 張，原為 2,967 張）
- 標準答案直接自 pylidc 的 `cluster_annotations()` 取得結節身分、中心與直徑，不再重新聚合
- 命中判定改為三維距離（mm）< 結節半徑，同 LUNA16
- 醫師人數 < 3 的結節設為忽略區；同一結節的重複偵測不計為誤報
- 預測的 3D 聚合改為「相鄰切片且框重疊」，不用固定像素門檻；分數隨框傳遞

**同一權重（yolo11s / 960）在兩種評估下的結果**

| | 抽樣切片（v1） | 完整掃描（v2） |
|---|---|---|
| 切片數 | 2,967 | 26,707 |
| 評估結節 | 189 | 191 |
| 候選 TP / FP | — | 180 / 6,098 |
| 落入忽略區 / 重複命中 | — | 90 / 17 |
| 召回率 @2FP | 0.878 | 0.822 |
| 95% CI | [0.833, 0.920] | [0.768, 0.882] |
| CPM | 0.844 | 0.717 |

FROC（v2）：0.435 / 0.592 / 0.670 / 0.764 / 0.822 / 0.853 / 0.880

**解讀**

- 191 vs 189：確認初版聚合確實併掉兩顆結節。
- 低假陽性區下降最多（0.125 FP/scan：0.693 → 0.435）。切片數增為九倍，同一門檻下誤報自然增加，這正是初版被高估之處。
- 90 個候選落在忽略區，即模型偵測到 103 顆低共識結節中的近九成。初版無忽略區，這些全數計為誤報。
- conf 0.01 時可找到 180/191，但每次掃描約 58 個候選。此為缺乏第二階段假陽性抑制的直接後果，對 2D 單階段偵測器屬合理範圍。

**關於重用 test 集**：權重未變，僅以修正後的量尺重測一次，不涉及模型選擇。此後不再因評估結果調整模型。

**附帶更正**：README 原將 `build_lidc_yolo.py` 的固定標註列為「原版本的限制」。經比對原專題報告，部署模型係以 Roboflow 標註訓練，該腳本與部署模型的關係無法確認，已改為說明性質的敘述。
