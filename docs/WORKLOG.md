## 一、原版本的問題與改善方法

| # | 問題 | 改善方法 |
|---|------|---------|
| 1 | 以「切片」為單位計算醫師共識。LIDC 由 4 位醫師獨立判讀，同一切片可能有多顆結節；A 醫師標結節甲、B 醫師標結節乙會被誤判為兩人對同一顆有共識，後續 9 項特徵取中位數時亦混合不同結節的評分 | 以 `cluster_annotations()` 依三維位置將標記歸群為物理結節，共識判斷改於結節層級進行 |

## 二、重建流程

```
環境建置 → 資料下載 → 前處理 → 目視驗證 → 病人層級切分 → 訓練 → 完整掃描匯出與檢查 → 病灶層級評估
```

### 環境

前處理與訓練分為兩個 conda 環境。pylidc 相依舊版 numpy 與 SQLAlchemy，與 ultralytics 的需求衝突。

版本鎖定原因：`numpy<1.24`（1.24 移除 `np.int`）、`sqlalchemy<2.0`（變更了 pylidc 使用的 Query API）、`setuptools<81`（移除 pylidc 於 import 時需要的 `pkg_resources`）。

**安裝說明更正**：不能把「PyPI 上的 torch 一律是 CPU 版」當通則。新建環境時依 [PyTorch 官方安裝頁](https://pytorch.org/get-started/locally/)選擇平台與 CUDA 支援，再實際檢查 `torch.cuda.is_available()`。原已能完成實驗的環境不因文件校正而重裝。

### 前處理

`cluster_annotations()` 歸群 → 篩共識 ≥3 位 → `consensus(0.5)` 計算框 → 轉肺窗存 PNG → 抽負樣本 → 輸出 YOLO 標註與 manifest。

產出：696 位病人、19,714 張影像（正 7,888 / 負 11,826）、8,208 個框、1,392 顆合格結節。含多顆結節的切片 309 張。

### 目視驗證

既有工作紀錄：將框畫回影像進行目視檢查，記下灰階平均值約 107，並查看框的位置、大小變化與多結節切片。此處未附逐張審閱清單；這些觀察不代表所有影像、亮度或標註都已全面確認。

數字正確不代表影像正確——框偏移、座標軸顛倒這類錯誤不會產生錯誤訊息。

### 切分

病人層級分層切分 70/15/15 → 487 / 105 / 104 位病人，框數比例 70.1% / 15.0% / 14.9%。

註：train 的切片厚度中位數為 2.00mm，val/test 為 1.25mm。分層依框數進行，厚度未納入條件。

### 訓練

YOLO11n + COCO 預訓練，imgsz 640、batch 8、patience 30。

### 評估

完整掃描推論 → 預測候選跨切片聚合 → 本專案毫米中心距離配對 → FROC 與 CPM → 病人層級 bootstrap 信賴區間。指標與配對概念參考 LUNA16，不等於完整官方實作；當前規則見 METRICS。

## 三、設計決定

**框的幾何：`consensus(clevel=0.5)`**
4 位醫師畫出 4 個不同輪廓（實測同一顆結節的直徑可差 43%：19.5 / 27.7 / 28.0 / 20.6 mm），但 YOLO 標註只能有一個框。`clevel=0.5` 取至少半數醫師認定屬於病灶的像素。替代方案為取聯集（框偏大）或取交集（可能切掉毛刺狀邊緣，而該特徵與惡性度相關）。選 0.5 是本專案的幾何定義；未以對照實驗證明其優於所有其他整合方式。

**共識門檻：≥3 位醫師**
本專案採 ≥3 作為納入條件；門檻與文獻相似，不代表資料與評估協定相同。既有統計為 2,651 顆中 1,392 顆合格，1,259 顆未達門檻（771 顆僅 1 位、488 顆有 2 位），約 47.5%。單看結節計數，改成 ≥2 會把 488 顆納入，使 1,392 增至 1,880，約增加 35.1%；**舊文的 29% 與這組數字不符**。這不等於可用切片或框數同樣增加 35.1%，仍受切片排除與其他條件影響；對照實驗未進行。

**低共識結節：連同該切片排除**
本專案在訓練資料建置時排除涉及低共識結節的切片，避免只刪標註卻保留未標註目標。這是目前選擇，不是唯一可能的方法，也不代表低共識標註必然錯誤；例如忽略區或其他標註策略需另行設計與驗證。完整掃描評估則不排除這些切片，而依 `gt.json` 的忽略區規則處理候選。

**切片厚度：不篩選，但記錄於 manifest**
實測中位數 2.0mm，≤2.5mm 者佔 88%，篩選僅損失一成多。保留可供後續分析模型在薄／厚切片上的表現差異。厚切片吃虧兩處：結節物理大小固定，切得越厚產出的訓練影像越少（實測一顆 20–28mm 結節在 3mm 切片上僅出現 6 張，1mm 切片約 20 張）；且部分容積效應使小結節邊界模糊。

**負樣本：正樣本 × 1.5，取自同批病人，距標註切片 ≥2 張**
訓練時按正樣本切片數的 1.5 倍抽取負樣本，用以控制資料量與背景比例，並從同批病人取樣以減少來源不一致的疑慮。`NEG_MARGIN=2` 為目前選擇的索引間隔。這些是設計考量，未經對照實驗證明比例最優、其他病人必然導致捷徑，或兩張切片的間隔可排除全部目標邊緣。完整掃描評估不採此負樣本抽樣。

**輸出格式：8-bit 灰階 PNG**
為維持既有推論輸入一致並方便目視除錯，本專案使用 8-bit 灰階 PNG。未與高位深輸入做對照，不能把 256 階足夠當成已驗證結論。

**肺窗：WC −600 / WW 1500**
選 WC −600／WW 1500 的主要理由是與既有推論流程一致，讓本專案的訓練與推論採同一套處理。未比較其他窗值，不能稱此組最優；此處不另指定臨床合理範圍。

**資料集：續用 LIDC-IDRI，不改用 LUNA16**
選擇繼續處理原專題使用的 LIDC-IDRI，以便追蹤同類原始影像與標註的處理方式。這是重建範圍的選擇；由於前處理、篩選與評估亦有變更，不能因此宣稱與原專題構成嚴格的單一變因對照，也不把 LUNA16 描述為可直接替換的 YOLO 真實框資料。

（過程中一度誤以為原專題使用 LUNA16，因 `dataloader.py` 有 `LUNA16_DIR` 變數名，但其實際掃描的是 LIDC 的 XML 格式。向組員確認後確定為 LIDC。後續查閱原專題報告發現，報告中亦將資料集稱為 LUNA16 而同時敘述 XML 標註，此一名稱上的混用貫穿文件與程式碼，詳見第四節。）

**切分：病人層級 + 分層 + assert 驗證**
依既有工作紀錄，切分時參考每位病人的框數進行分層，並以 assert 檢查三組病人無重疊。這可以檢查同病人跨組，但不能單靠框數保證各組病灶難度、掃描條件完全相同，也不是所有資料洩漏類型的完整檢查。

**預訓練權重：使用 COCO 預訓練**
當時訓練框數記錄為 5,754，選擇預訓練初始化是為降低從零訓練的成本並作為實作起點。尚未做同條件的預訓練／隨機初始化對照，不能確定其改善幅度，也不能推定從零訓練必然嚴重過擬合。

**模型：yolo11n 偵測版，非 yolo11m-seg**
本次以框偵測為目標，因此採偵測模型而非分割模型。歷史紀錄中的權重大小為原版本約 114MB、yolo11n 約 5.5MB；檔案大小本身不足以判定原模型的任務類型或造成差異的確切原因。

**資料增強：依 CT 特性調整**

| 參數 | 預設 | 調整為 | 理由 |
|---|---|---|---|
| hsv_h, hsv_s | 有 | 0 | 灰階影像無色相與飽和度資訊 |
| hsv_v | 0.4 | 0.15 | 本次重建的核心為統一灰階標準，過大的亮度抖動會重新引入該變異 |
| flipud | 0 | 0 | 上下翻轉的胸腔影像解剖上不存在 |
| fliplr | 0.5 | 0.5 | 左右鏡像雖然左右肺結構不同，但對「找出團塊」仍屬合理變化 |
| degrees | 0 | 10 | 病人擺位傾斜是真實存在的變異 |

**信賴區間：以病人為單位 bootstrap**
為保留病人內的群集結構，bootstrap 將同一病人的掃描、結節與候選紀錄整批重抽，不把每顆結節當作獨立抽樣單位。此程序描述的是固定模型及評估設定下的樣本波動，不涵蓋全部方法與外部資料的不確定性。

**更正**：`evaluate.py` 仍保留 `r2 >= 1.0` 時列印 `3/n_gt` 的舊提示，但沒有替換 JSON 中的 bootstrap 區間，也沒有確認獨立二項假設。FROC 操作點滿分不自動代表 bootstrap 必然退化。本次未觸發該提示，當前 CI 由病人 bootstrap 計算；詳細限制見 [METRICS](METRICS.md)。

## 四、實驗紀錄

### mosaic 增強：從初步結論到修正

當時擔心 mosaic 拼接改變 CT 影像的空間連續性，因此進行開／關比較。這是實驗起始假設，不是本專案已證明 mosaic 普遍不適用於醫學影像。下表屬舊版 val／抽樣評估。

| | 159 位病人 | | 696 位病人 | |
|---|---|---|---|---|
| | mosaic 開 | mosaic 關 | mosaic 開 | mosaic 關 |
| CPM | 0.873 | 0.845 | 0.827 | 0.845 |
| 召回率 @2FP | 0.913 | 0.848 | 0.884 | 0.874 |
| 95% CI | [0.796, 1.000] | — | [0.837, 0.935] | [0.826, 0.926] |
| val 結節數 | 46 | 46 | 207 | 207 |

159 位資料的初步紀錄顯示，關閉 mosaic 後 Recall 降低 0.065。開啟組 CI 為 [0.796, 1.000]；關閉組在本表未記錄 CI，因此舊文「兩組區間大幅重疊」缺少資料支持。僅靠這次點估計無法確認差異是否穩定。

擴增至 696 位病人重測後，差異縮小至 0.01 且方向不一致（CPM 為關閉較好、召回率為開啟較好），兩組信賴區間幾乎完全重疊。

**目前可支持的觀察**：兩個資料規模下，CPM 與 Recall 的變化方向不完全一致。未進行多種子重複訓練或配對差異分析，因此不能確定「mosaic 沒有效果」，也不能直接把初步差異歸因於小樣本雜訊；兩組 CI 是否重疊不足以完成此判斷。

註：第一次訓練（159 位、mosaic 開）的 `experiment.json` 因路徑處理錯誤未能寫出，其設定與後續三次相同，僅資料量不同。該錯誤已修正（改由 `model.trainer.save_dir` 取得實際輸出位置）。

註：上表數字為檔名衝突修正前所測。修正後於相同權重重新評估，696 位／mosaic 開的 CPM 為 0.830、召回率 @2FP 為 0.885，變動在 0.003 以內。

### 資料量擴增：歷史點估計與區間變化

| | 159 位病人 | 696 位病人 |
|---|---|---|
| val 結節數 | 46 | 207 |
| 召回率 @2FP | 0.913 | 0.884 |
| 95% CI | [0.796, 1.000] | [0.837, 0.935] |
| 區間寬度 | ±0.10 | ±0.05 |

召回率下降 0.029，但信賴區間收窄一半。

46 顆中漏 4 顆約為 0.913，207 顆中漏 24 顆約為 0.884。表中後一次區間較窄，但資料與模型實驗條件不同，不能只憑此認定模型未退步或結果更接近外部真實表現。**更正：0.913 位於 [0.837, 0.935] 之內**，舊文「落在新區間之外」為錯誤；點估計落入另一組區間也不能取代差異分析。

原紀錄另列出 159 位版與 696 位版部分 FROC 值（0.783 → 0.826、0.647 → 0.850）。此處未列出對應操作點，且評估資料不同，保留數值為歷史資訊，不據此判定信心分數的鑑別力改善。

### 檔名衝突：發現、修正與影響評估

比對 `manifest.csv` 的列數（19,714）與實際輸出的 PNG 檔案數（19,680）時發現不一致，相差 34 張。

**原因**：檔名由 `patient_id` 與切片編號組成，未計入同一位病人可能有多次掃描（LIDC-IDRI 中確實存在）。第二次掃描的輸出覆蓋了第一次的同名檔案。

**影響分析**：

- 程式設計為影像與標註成對寫出，但沒有逐檔內容核對，不能僅據此保證所有覆蓋情況都維持正確對應
- 病人層級切分不受影響，兩次掃描的 `patient_id` 相同，必然分入同一組
- 但該病人的切片序列成為兩次掃描的混合，破壞了 3D 聚合「相鄰編號來自同一次掃描」的前提
- 評估時 `n_scans` 誤以病人數計算，使 FP/scan 的分母偏小

**修正**：檔名加入 `scan.id`；評估改以掃描為單位進行 3D 聚合與匹配，但 bootstrap 仍以病人為單位（同一病人的多次掃描不是獨立樣本）。

**修正後的影響量化**（yolo11n / 640，val 集）：

| | 修正前 | 修正後 |
|---|---|---|
| 掃描數 / 病人數 | 105 / 105 | 106 / 105 |
| 結節數 | 207 | 209 |
| 召回率 @2FP | 0.884 | 0.885 |
| CPM | 0.827 | 0.830 |
| 95% CI | [0.837, 0.935] | [0.839, 0.936] |

該次 val 紀錄中有 1 位病人有兩次掃描，表中修正前後數值的變化很小。這只支持此權重、此設定下的觀察，不能因差異小於 CI 寬度，就宣稱先前四組實驗的所有結論均已確認不受影響。

已於 `preprocess.py` 加入自動檢查：比對 manifest 列數、唯一檔名數與實際檔案數，不一致時發出警告。

### 評估方法的修正（2026-09）

將 repo 與同組同學的原專題 repo 一併交由另一個語言模型審閱，其指出評估程式的三項問題；自行複查後再確認三項。

**審閱指出的**

1. FP/scan 只算了抽樣切片。評估讀取的是訓練用的 `test.txt`，僅含正樣本切片與 1.5 倍抽樣負樣本，每次掃描約 30 張；實際一次 CT 有 200–300 張，未被抽入的切片可能產生的誤報完全未被計入。
2. 命中規則非完整 LUNA16 協定。使用像素距離與自訂聚合條件，且未處理 LUNA16 的「忽略區」（打中非參考標準的結節不計分）。文件卻寫「依 LUNA16 協定」。
3. 標準答案由 2D 框重新聚合。`cluster_3d()` 以固定 30 像素為門檻，同一切片上相距較近的兩顆結節會被併為一顆。人工案例可重現此行為。

**自行複查再發現的**

4. 匹配時要求預測與標準答案的 z 中心相差 ≤ 2 張。橫跨 20 張的大結節若只被抓到一端，兩中心相差可達 8 張，明明抓到卻判為漏診。
5. 半徑以像素計，但各掃描的 pixel_spacing 從 0.46 到 0.98 mm 不等，同一像素數代表的實際距離差一倍。
6. 聚合後的信心分數以四捨五入的座標查表回填，座標碰撞時會互相覆蓋。

**修正**（`export_eval.py` + 重寫 `evaluate.py`，舊版保留為 `evaluate_v1_sampled.py`）

- 對 test 集每次掃描輸出全部切片（26,707 張，原為 2,967 張）
- 標準答案直接自 pylidc 的 `cluster_annotations()` 取得結節身分、中心與直徑，不再重新聚合
- 命中判定改為三維距離（mm）< 結節半徑，參考 LUNA16 的中心距離概念；整套流程仍與官方不同
- 醫師人數 < 3 的結節設為忽略區；同一結節的重複偵測不計為誤報
- 預測聚合改採切片索引間隔與框尺度相關的平面中心距離，候選分數取最大；不是固定 30 像素，也不是實際 IoU 重疊判斷，詳見 METRICS

**同一權重（yolo11s / 960）在兩種評估下的結果**

| | 抽樣切片（v1） | 完整掃描（v2） |
|---|---|---|
| 切片數 | 2,967 | 26,707 |
| 評估結節 | 189 | 191 |
| 候選 TP / FP | — | 180 / 6,098 |
| 落入忽略區 / 重複命中 | — | 90 / 17 |
| 召回率 @2FP | 0.878 | 0.822 |
| 95% CI | [0.833, 0.920] | [0.768, 0.882] |
| CPM | 0.844 | 0.717 |

FROC（v2）：0.435 / 0.592 / 0.670 / 0.764 / 0.822 / 0.853 / 0.880

**解讀**

- **更正，191 vs 189**：人工案例已證明舊聚合有誤併風險，但總數差 2 不能確認實際恰好合併兩顆；資料範圍與參考標準亦有變更，仍須逐顆對照才能歸因。
- 低 FP 操作點的歷史數值由 0.693 變為 0.435。完整掃描納入更多可產生誤報的切片，但標準答案、聚合與配對也改變，不能將所有差異單獨歸因於切片數，或假定兩版逐候選分數相同。
- **更正，忽略候選**：90 為候選數，同一忽略結節可能有多個候選，不能換算成 103 顆的近九成；也未以逐候選對照確認這 90 個在舊版都曾出現或都被計為 FP。
- **更正，候選與 FP**：整批 6,385 個候選約為 60.8／掃描；其中 6,098 個 FP 約為 58.1／掃描。180／191 是這批低門檻候選的命中比例，不是 2 FP/scan 下的 Recall。未做第二階段抑制的對照，不能確定誤報主因或宣稱屬合理範圍。

**關於重用 test 集**：依本次實驗紀錄，先擴充為完整掃描評估，之後又修補評分邊界並重算（見第五節），均沿用既有定案權重，不是只重測一次。評分問題的修正與 test 使用歷程保留，不將這批資料再描述為完全未見的新測試集；後續模型與參數探索應回到 val。

**附帶更正**：README 原將 `build_lidc_yolo.py` 的固定標註列為「原版本的限制」。經比對原專題報告，部署模型係以 Roboflow 標註訓練，該腳本與部署模型的關係無法確認，已改為說明性質的敘述。
