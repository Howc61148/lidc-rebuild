# 評估指標說明

本文件說明本專案的指標、計分方式與解讀界線。2026-09-22 依修補後的 [`evaluate.py`](../evaluate.py)、[評估結果](../reports/eval_test_full_scoring_fixed.json)與 [audit 報告](../reports/audit_eval_test.json)校正；歷史實驗另行標示，不與目前 test 結果混用。

程式行為與實驗數據以以上檔案為依據；LUNA16、mAP 與 rule of three 的一般定義另附來源，不代表本專案已重現官方完整流程。

---

## 偵測結果的三種類型

在本專案的病灶層級評估中：

| 代號 | 名稱 | 本專案中的意思 |
|---|---|---|
| TP | 真陽性 | 納入評估的結節已被候選依配對規則命中，每顆最多計一次 |
| FP | 假陽性／誤報 | 候選未命中正式結節，也未被歸為忽略候選或重複命中 |
| FN | 假陰性／未命中 | 納入評估的結節在該操作點尚未被命中 |

**候選不只會成為 TP 或 FP**：落入忽略區及重複命中的候選另行計數，不納入本專案 FROC 的 TP／FP 累計。FN 則由未命中的參考結節計算，不是一種預測候選。

此處的「結節」指參考標準納入的結節，不是所有可能存在的病灶，也不是病理確診的惡性病灶。本評估未定義可供計算特異度的 TN 總數；不把這個設定擴張為所有偵測問題都不可能定義 TN。

---

## Recall（召回率／sensitivity／敏感度）

```text
Recall = TP / (TP + FN) = 被命中的評估結節數 / 評估結節總數
```

回答的是「參考標準中納入的結節，有多少被命中」。本專案的分母為 191 顆，不能使用 26,707 張切片或 105 次掃描代替。

目前 test 集完整掃描結果為 **0.822 @ 2 FP/scan**，原始值 `0.8219895287958116`，相當於該 FROC 操作點命中 157／191 顆。這不是分類準確率，也不是全體候選統計中的 180／191。

---

## FP/scan（每次掃描的平均假陽性數）

```text
FP/scan = 累計 FP 數 / 掃描次數
```

本次分母為 **105 次掃描**，不是 104 位病人。相同病人的多次掃描分別計入掃描數，但在 bootstrap 時仍隨病人整批重抽。

FP/scan 是平均誤報**數量**，不同於需要 TN 的比例 `FP / (FP + TN)`。本專案以它描述偵測結果的誤報負擔，不據此宣稱臨床可接受程度。

## 兩者的取捨關係

在預測聚合與配對完成、候選集合固定後，逐步降低保留候選的信心門檻：

| 門檻變化 | 累計 Recall | 累計 FP/scan |
|---|---|---|
| 調高 | 不增加 | 不增加 |
| 調低 | 不減少 | 不減少 |

兩者可以維持不變，不是每次調整都嚴格上升或下降。降低門檻也不保證召回率達 1.0，因為未產生候選或未符合配對規則的結節不會自動被補回。

本次先以推論門檻 `conf=0.01` 產生二維框，再固定聚合結果，掃描候選信心門檻；不是在每一個 FROC 點重新推論與聚合。低於本次推論門檻的輸出未納入結果。

## FROC 曲線

Free-response ROC：橫軸為 FP/scan，縱軸為病灶召回率。本專案沿用此指標形式，不使用 TN 作為橫軸分母。

目前程式的計算步驟如下：

1. 將計分候選依信心分數由高到低排序。
2. **完全相同分數的候選一起累計**，不能因輸入排列不同，在同一分數門檻下只保留其中部分候選。程式不先四捨五入分數。
3. 每個不同的分數門檻產生一個 `(FP/scan, Recall)` 點。
4. `sens_at(curve, x)` 取 `FP/scan <= x` 的所有曲線點中最高的 Recall；沒有符合點時回傳 0。**這是階梯式取值，不做線性插值。**

因此，`Recall @ 2 FP/scan` 指不超過該平均 FP 數條件下的取值，不保證正好產生每次 2 個 FP，也不是已選定可直接部署的固定信心門檻。

本次 test 結果（104 位病人、105 次掃描、191 顆評估結節）：

| FP/scan | 0.125 | 0.25 | 0.5 | 1 | 2 | 4 | 8 |
|---|---|---|---|---|---|---|---|
| Recall | 0.435 | 0.592 | 0.670 | 0.764 | 0.822 | 0.853 | 0.880 |

以結果 JSON 的未四捨五入數值計算，4 到 8 FP/scan 的召回率增加 `0.8795811518 − 0.8534031414 = 0.0261780105`，約 **2.6 個百分點**；舊文的 `0.015` 為計算錯誤。這項觀察本身不能確定各個未命中案例的成因。

本次全部聚合候選共有 6,385 個：180 TP、6,098 FP、90 個忽略候選、17 個重複命中。對應約 **60.8 個候選／掃描**與 **58.1 個 FP／掃描**；整批候選的 180／191 約為 94.2%，不能配上「2 FP/scan」一起報告。

在本次推論、聚合與配對設定下，有 11 顆評估結節未命中。未保存及逐例分析原始候選前，不能說它們「完全沒有任何框」或「任何門檻都找不到」。也不能由此指定一個普遍適用的臨床可接受 FP 範圍。

## CPM（Competition Performance Metric）

本專案取 FROC 上七個指定 FP/scan 點（0.125、0.25、0.5、1、2、4、8）的 Recall 平均，使用未四捨五入的數值計算：

```text
CPM = 七個操作點的 Recall 總和 / 7
```

本次為 `0.7165295437546746`，顯示為 **0.717**。七點指標形式參考 [LUNA16 論文第 3.3 節](https://arxiv.org/abs/1612.08012)。

使用相同指標能統一摘要方式，但不會使不同實驗變成公平比較。本專案的資料範圍、病人切分、參考標準、忽略標註範圍與評分實作均需另外交代；目前不是 LUNA16 官方資料與完整評估流程，不與榜單直接比較。

## mAP50／mAP50-95

本專案的 YOLO 訓練紀錄使用二維切片框標註，訓練時顯示的 mAP 屬於此層級的評估，與病灶層級 FROC 不同。

**IoU（交集比聯集）**為預測框與參考框交集面積除以聯集面積，完全重合時為 1。IoU 0.5 指交集占聯集一半，不是任意一個框有一半面積重疊。

- **mAP50**：在 IoU 門檻 0.5 下計算 AP，並依類別取平均；不是單一信心門檻的 Recall。
- **mAP50-95**：在 IoU 0.50 至 0.95、間隔 0.05 的十個門檻計算後取平均，不代表每個候選都必須達到 0.95。

一般定義參考 [Ultralytics 指標說明](https://docs.ultralytics.com/guides/yolo-performance-metrics/)。

小框對位置偏差的 IoU 變化可能更敏感，但沒有相同資料與方法的參考比較，不能將歷史數值 0.406–0.418 宣稱為「正常範圍」。本專案將 mAP 作為二維訓練觀察，將病灶層級 FROC 作為主要結果；不是因為前者一定低估、後者一定更高。

## 切片層級 vs 病灶層級

一顆結節可能跨越多張切片。切片層級評估比較每張切片上的框；病灶層級評估則使用結節身分及跨切片候選。兩者計數單位與命中條件不同，不能只比較數字大小來判斷哪一個更準確。

以下保留原工作紀錄的歷史示例，**不是目前完整掃描 test 結果，也不是新評估規則下的受控比較**：

| 歷史紀錄的評估層級 | Recall |
|---|---|
| 切片層級 | 0.684 |
| 舊版病灶層級 | 0.885 |

原紀錄指出使用相同模型，但兩種數值的統計單位、門檻與評分方式不同；不能把差額當成模型能力提升，也不能推論「任一切片被標出就一定能讓醫師注意到」。

## 3D 聚合

**本節僅指預測候選的聚合。**正式參考結節直接讀取 `export_eval.py` 匯出的 `gt.json`，不再由二維標註框重新聚合。

目前 `cluster_predictions()` 的實際規則為：

1. 預測框依切片索引 `z` 排序，以既有候選的順序尋找第一個符合者。
2. 與候選最後一張切片的索引差不超過 `MAX_SLICE_GAP=2`；程式也可能比較同一張切片上的框。
3. 令當前框 `r=max(w,h)/2`，候選最後一個框的對應值為 `rr`；若平面中心距離 `<= max(r,rr)`，即合入候選。
4. 候選中心為所納入框中心 `(x,y,z)` 的算術平均，候選信心分數取最大值。

這是**框尺度相關的中心距離啟發式**，不是固定 30 像素，也不是直接計算二維框 IoU；「框重疊」僅是舊註解的簡稱。聚合處理與後續毫米距離配對是不同步驟。

這個規則不是經驗證的最佳聚合方法，也不保證所有接近的候選都能正確區分；此處說明既有程式，不在本次文件更新中更改算法或重新調參。

## 命中判定（參考 LUNA16 的中心距離概念）

`match_scan()` 逐次掃描處理候選，依信心分數由高到低進行：

1. 像素中心 `(x,y,z)` 以該掃描的 `pixel_spacing_mm` 與 `slice_spacing_mm` 換算為 `(x*ps, y*ps, z*ss)`。
2. 優先尋找所有 `status="included"` 且三維中心距離 **嚴格小於** 結節半徑的正式結節；若符合多顆，沿用最近中心的指定方式，不是全域最優配對。
3. 若指定結節尚未命中，計 TP；已命中則記為重複命中，不另外計 TP／FP。
4. **沒有匹配正式結節時**才檢查 `status="ignore"` 區域，落入者記為忽略候選。
5. 其餘候選計 FP。

正式結節與忽略區重疊時，正式結節優先。90 個忽略候選是候選數，不等於 90 顆不同的忽略結節。

本次 audit 記錄 105 次掃描皆完成 z 位置檢查，最大固定間距映射誤差約 `0.00003 mm`，低於工具容差 `0.01 mm`。這是相對位置與資料庫記錄的檢查，**不是完整 DICOM 實體座標轉換驗證**；工具未逐張重讀 DICOM header，也未驗證方向矩陣或 gantry tilt。[pylidc 文件](https://pylidc.github.io/_modules/pylidc/Scan.html)將 `slice_spacing` 定義為切片位置差的中位數，因此換資料時仍需要檢查等距前提。

配對概念參考 [LUNA16 第 3.3 節](https://arxiv.org/abs/1612.08012)；本專案的參考標準與忽略區並不等於官方完整標註集合，不能只因中心距離規則相似，就稱為完整遵循 LUNA16。

## 信賴區間

### 要解決的問題

本次 0.822 是既定 test 樣本及評估流程的結果。病人重抽樣用來檢視此批樣本組成變動時，該統計量的波動，不代表把模型、標註、前處理或外部資料差異都納入不確定性。

較窄的區間通常表示在所採估計程序下抽樣波動較小，不等於資料無偏、程式正確或臨床可靠。

### Bootstrap

目前 `bootstrap_ci()` 的程序為：

1. 從 **104 位病人**的索引中，有放回抽取 **104 次**。
2. 每次抽到病人時，將其全部掃描數、評估結節數與計分候選紀錄一起加入；同一病人可被抽到多次。
3. 重新計算該重抽樣本的 FROC，按相同階梯式規則取 `Recall @ 2 FP/scan`。不是先算每位病人的 Recall 再平均。
4. 以 `seed=42` 重複 1,000 次，取有效結果的第 2.5 與第 97.5 百分位數；程式遇到零結節或零掃描的樣本會略過。

本次區間為 **[0.768, 0.882]**，對應 `Recall @ 2 FP/scan`，不是 CPM 的信賴區間。104 是病人數；105 是掃描數，不能混用。

### 以病人為單位，而非結節

本專案選擇保留同一病人內掃描與結節的群集結構。例如某病人有多顆結節，它們在重抽時一起進出，而不是各自被視為獨立樣本。

這是本次估計的抽樣單位選擇，不代表僅靠病人 bootstrap 就已涵蓋所有不確定性。區間也不能只以是否重疊，代替兩個方法差異的正式比較。

### 本專案的區間變化（歷史 val 紀錄）

以下是舊版抽樣評估及檔名衝突修正前的紀錄，**不是目前 test 結果**：

| 資料建置病人數 | val 結節數 | Recall @ 2 FP/scan | 95% CI | 區間全寬 |
|---|---|---|---|---|
| 159 | 46 | 0.913 | [0.796, 1.000] | 0.204 |
| 696 | 207 | 0.884 | [0.837, 0.935] | 0.098 |

本表數值顯示後一次區間較窄，但資料與模型實驗條件有變，不能據此斷言「不是模型退步」或「更接近真實表現」。**更正：0.913 位於 [0.837, 0.935] 之內**，舊文「落在區間之外」為錯誤；也不能用點估計是否落入對方區間來取代配對比較。

檔名衝突修正後，相同權重的舊版 val 紀錄為 209 顆結節、Recall 0.885、CI [0.839, 0.936]。保留原表的 207 作為歷史紀錄，不全域替換為 191 或 209；詳見 WORKLOG 第四節。

## Rule of three

**本次的信賴區間不是用這個方法計算。**

對固定、全部成功的二元結果直接進行一般非參數重抽，可能得到 [1,1] 的退化區間，但不能據此認定估計完全確定。在獨立且事件機率相同的二項試驗假設下，零次失敗的近似單側 95% 失敗率上界為 `3/n`；它是有條件的近似，不是滿分指標的通用修正。來源：[Hanley & Lippman-Hand, 1983](https://jhanley.biostat.mcgill.ca/c607/ch08/zero_numerator.pdf)。

例如，只有在上述假設成立時，33 次試驗零失敗才能將 `3/33 ≈ 9.1%` 解讀為近似上界。同病人的結節可能相依，FROC 又涉及 FP 預算與門檻，因此不能直接以結節數套用此結論。

目前程式仍保留 `r2 >= 1.0` 時列印 `3/n_gt` 的舊提醒；**該分支沒有替換 JSON 中的 bootstrap 區間，也沒有檢查二項試驗假設或 bootstrap 是否真的退化**。本次 `r2=0.822` 未觸發此分支。此次只校正文件、不變更已用於重算的 `evaluate.py`；日後若觸發提醒，不應直接當成有效的病人層級 FROC 區間。
